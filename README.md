# telebot-maverick

Торговый бот по сигналам Telegram-ботов Maverick (метрики Deep Global / Local / Scalp), бэктест и интерактивный интерфейс
для просмотра сделок на графике.

```
backend/     Python: FastAPI-API для интерфейса, движок бэктеста, Telegram-бот и экспорт истории
  app/core/    движок: симуляция сделок (backtest.py), точки входа и фильтры (entries.py), разбор сообщений (signal_parser.py)
  app/         API: config.py (env), data.py (источники и свечи), service.py (запуск бэктеста), state.py, main.py
  tools/       bot.py, trader.py (биржа), export_history.py (выгрузка истории из Telegram)
  tests/       pytest: движок, API, экспорт
  cli.py       консольная точка входа: serve | backtest | export | bot
signalbot/   Telegram-бот сигналов: принимает конфиги (файлом/текстом) и присылает новые сигналы со статистикой конфига (см. signalbot/README.md)
frontend/    React + TypeScript + Vite + lightweight-charts: график, сигналы, TP/SL, статистика
e2e/         проверка интерфейса в настоящем браузере на синтетических данных
```

Пользовательские данные лежат в **корне репозитория** и не коммитятся: `history*.csv` (выгрузки), `data/` (кеш свечей и
`ui_state.json` с вашим выбором), `*.session` (сессии Telegram), `trades.csv`.

## Пользователи и вход

На сайт входят по логину и паролю. **Регистрации на сайте нет** — пользователей создаёт администратор в консоли сервера:

```bash
cd backend
python cli.py user add ЛОГИН         # пароль спросит; первый пользователь — администратор
python cli.py user list              # passwd / disable / enable / remove / link / unlink / link-code / import-legacy — python cli.py user -h
```

После входа подгружаются последние сохранённые настройки именно этого пользователя (выбор источника и актива, параметры по каждой связке, таймфрейм);
конфиги бота сигналов и привязка Telegram — тоже его. Всё хранится в SQLite (`data/maverick.db`, `DB_FILE`). **Данные рынка общие для всех** (история
сообщений ботов, свечи, активы из «＋ Добавить актив…») — их никто не качает заново. Пароли хранятся хэшем (scrypt), сессия — HttpOnly-cookie
(`SESSION_DAYS`, `COOKIE_SECURE=true` за HTTPS), есть защита от перебора пароля и CSRF. Если до этого пользователь был один (вы), первый
`user add` переносит ваши прежние настройки и конфиги бота в его аккаунт. `AUTH_ENABLED=false` отключает вход (только для локальной разработки).

## Быстрый старт

```bash
# 1. Бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # заполнить: источники, активы, параметры стратегии (+ Telegram/биржа для бота)
python cli.py serve               # API на http://127.0.0.1:8000  (python cli.py serve --reload — с автоперезагрузкой)

# 2. Интерфейс (в другом терминале)
cd frontend
cp .env.example .env              # необязательно
npm install
npm run dev                       # http://localhost:5173, /api проксируется на бэкенд
```

Свечи: в интерфейсе кнопка **«Обновить свечи»** (или `python cli.py backtest …`) скачивает их с биржи в `data/`.

## Конфигурация (`backend/.env`)

Все важные значения — в одном файле `backend/.env` (шаблон — `backend/.env.example`). Им пользуются и API, и бэктест, и бот,
поэтому интерфейс и бот не расходятся в параметрах.

| Группа | Переменные |
|---|---|
| Источники метрик | `SOURCES=coinbase,binance`, `SOURCE_<ID>_FILE`, `SOURCE_<ID>_LABEL`, `SOURCE_DEFAULT`, `LIQ_SOURCE`, `LIQ_MAX_AGE_H` |
| Активы и свечи | `EXCHANGE`, `SYMBOLS`, `SYMBOL_DEFAULT`, `CANDLE_TF`, `CACHE_DIR`, `MAX_BARS` |
| Пользователи | `AUTH_ENABLED`, `DB_FILE`, `SESSION_DAYS`, `COOKIE_SECURE`, `SIGNALBOT_USERNAME` |
| Сервер | `HOST`, `PORT`, `CORS_ORIGINS`, `ASSETS_FILE` (`STATE_FILE` — только источник для переноса старых настроек) |
| Стратегия (умолчания) | `SIDE`, `ONLY`, `LOCAL_MIN`, `SCALP_MIN`, `SHORT_LOCAL_MAX`, `SHORT_SCALP_MAX`, `CONFIRM`, `TP_PCT` или `TP_LEVELS`, `BE_AFTER_TP1`, `SL_PCT`, `DEPOSIT`, `TRADE_PCT`, `LEVERAGE`, `COMPOUND`, `FEE`, `SLIPPAGE` |
| Тренд (умолчания) | `TREND_ENABLED`, `TREND_EMAS` (20,50,100,200), `TREND_TF` |
| Топ-коины (умолчания) | `TOP_ENABLED`, `TOP_SIDES`, `TOP_TP_PCT` или `TOP_TP_LEVELS`, `TOP_BE_AFTER_TP1`, `TOP_SL_PCT`, `TOP_SIZE_USD`, `TOP_FEE`, `TOP_SLIPPAGE`, `TOP_DAYS`, `TOP_MIN_VALUE` |
| Фильтры (умолчания) | `COOL_METRIC`, `COOL_DROP`, `COOL_DECLINES`, `LIQ_HOURS`, `LIQ_FRAC`, `LIQ_PCT`, `COOLDOWN_H` |
| Автоподгрузка свечей | `CANDLES_SYNC`, `CANDLES_SYNC_MIN` (5), `CANDLES_SYNC_SYMBOLS` |
| Telegram и биржа (бот, экспорт) | `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`, `TG_CHANNEL_ID`, `API_KEY`, `API_SECRET`, `API_PASSWORD`, `DRY_RUN` |

Старый формат (`HISTORY_FILE`, `LIQ_FILE`, `SYMBOL`) тоже понимается. Корневой `.env` читается как запасной.

## Интерфейс

- **График** свечей с маркерами входа (▲ лонг / ▼ шорт) и выхода (TP / SL / REV / OPEN), линиями входа, тейка и стопа на время
  сделки и, по желанию, пропущенными сигналами. Клик по сделке на графике или в таблице приближает к ней.
- **Таймфрейм**: «Авто» подбирает под масштаб, либо фиксированный (1m … 1d). Листание и зум подгружают свечи; смена ТФ
  сохраняет вид и выбранную сделку; ← / → — предыдущая/следующая сделка.
- **Параметры**: актив, источник метрик (Coinbase / Binance Maverick) и отдельно источник ликвидаций, сторона, режим «только Local /
  только Scalp», пороги, подтверждение, TP/SL, комиссия, проскальзывание, пауза после стопа, фильтры «остывание метрик» и
  «ликвидации закончились», период. У каждого параметра значок **«?»** с описанием, как он работает (тексты — `frontend/src/helpTexts.ts`).
- **Статистика**: итог, число сделок, winrate, profit factor, просадка, средние, серия убытков, время в позиции; разрезы по
  сторонам и половинам истории; результаты по месяцам; кривая капитала; таблица сделок.
- **Активы**: в списке «Актив» — `SYMBOLS` из `.env`, а пункт «＋ Добавить актив…» добавляет новый прямо из интерфейса. Достаточно
  написать `ETH`, `ETHUSDT`, `ETH/USDT` или полный символ. Бэкенд проверяет, что такой бессрочный контракт есть на бирже
  (при опечатке подскажет похожие), запоминает актив в `ASSETS_FILE` и **скачивает свечи в фоне**: интерфейс не блокируется, в
  шапке виден ход загрузки. Когда загрузка закончится (или завершится ошибкой с причиной), придёт уведомление в приложении
  (с кнопкой «Открыть …») и системное уведомление браузера, если вкладка в фоне и вы разрешили их. Уведомление не теряется,
  если страницу перезагрузили или закрыли во время загрузки: оно показывается, пока вы его не закроете. «Обновить свечи» тоже
  работает в фоне. Добавленный из интерфейса актив можно убрать из списка (файл со свечами остаётся на диске).
- **Депозит, доля на сделку, плечо**: размер каждой сделки = текущий баланс × «доля депозита» × плечо (баланс = депозит + закрытые результаты, то есть
  со сложным процентом; если баланс упал до нуля, торговля прекращается). Доходность на объём от плеча не зависит, суммы в $ растут пропорционально.
  Галочка «сложный процент» выключена — простой процент: каждая сделка на одну и ту же сумму (доля от начального депозита × плечо).
  Если плечо × стоп ≥ 100%, показывается предупреждение: на бирже позицию ликвидировали бы раньше стопа, а бэктест ликвидацию не моделирует.
  В статистике — доходность от депозита, просадка в % от пика и **коэффициент Шарпа**: годовой, по дневным доходностям баланса (результат за день /
  баланс на начало дня, дни без сделок = 0, × √365, безрисковая ставка 0). При менее чем двух днях истории или нулевом разбросе показывается «–».
  Топ-коины по-прежнему торгуются фиксированной суммой в $ и в Шарпе не участвуют.
- **Тренд**: чекбокс «торговать только по тренду» оставляет лонги, когда цена выше выбранных EMA (20/50/100/200, можно несколько — цена должна быть по
  нужную сторону от всех), и шорты, когда ниже. EMA считается по закрытым свечам выбранного таймфрейма (по умолчанию 1h) на момент сигнала, без
  заглядывания вперёд; пока свечей меньше периода самой длинной EMA, сделки не открываются. Фильтр относится к основному активу; сигналы для топ-коинов он не
  режет. Отсечённые сигналы считаются в чипе над графиком и в «пропущенных».
- **Топ-коины**: в каждом отчёте есть блок Top Coin — первая строка (`TIA-USD | 10.12`) это топ-коин. Когда основная стратегия
  (по вашим параметрам) подтверждает сигнал, по этой монете в тот же момент открывается сделка в ту же сторону со **своими** настройками
  (тейки частями, безубыток, стоп, размер в $, комиссия, проскальзывание — секция «Топ-коины» в параметрах). Результаты — на отдельной
  вкладке «Топ-коины»: статистика, разрез по монетам, график монеты (клик по сделке или по монете), кривая капитала и список
  пропущенных сигналов с причинами (нет топ-коина в отчёте, нет фьючерса на бирже, значение ниже порога, по монете уже есть позиция…).
  Свечи монет качаются **только на окно «момент сигнала + `TOP_DAYS` суток»** (по умолчанию 3) — кнопкой «Скачать свечи» на вкладке: в
  фоне, с уведомлением; уже скачанные окна повторно не качаются (карта окон `*.windows.json` рядом с кешем). После загрузки сделки
  пересчитываются сами. Если за окно не сработали ни тейк, ни стоп, позиция закрывается по рынку (причина TIME); для свежих сигналов
  окно ещё не закончилось — такие сделки помечены ⏳. Тикер из отчёта сопоставляется с бессрочным USDT-контрактом биржи (`TIA-USD` →
  `TIA/USDT:USDT`, `PEPEUSDT` → `1000PEPE/USDT:USDT`); у монет без фьючерса (например `WBETHUSDT`) сделки не открываются. По монете одна позиция
  одновременно: следующие сигналы, пока она открыта, пропускаются.
- **Текущие метрики и автоподгрузка истории**: в полосе «Сейчас» под шапкой — последние DG / DL / DS каждого бота (DL и DS зелёные при условии лонга
  ваших параметров, красные при условии шорта), время отчёта и топ-коин. Сервер сам подгружает новые сообщения обоих ботов из Telegram **при запуске и затем
  каждые 32 минуты** (`HISTORY_SYNC_MIN`); кнопка «Обновить сейчас» запускает подгрузку немедленно. Когда пришли новые сообщения, появляется уведомление с
  кнопкой «Пересчитать» (расчёт не меняется сам, чтобы не сбивать выбранную сделку); свечи для новых отчётов докачиваются кнопкой «Обновить свечи».
  Чаты задаются `SOURCE_<ID>_CHAT` (по умолчанию coinbase → `TG_CHANNEL_ID`, binance → 2119980662). Нужны `TG_API_ID`, `TG_API_HASH` и уже авторизованная сессия
  Telegram: один раз выполните `python cli.py export …` и введите код — сервер сам кода не спрашивает и при неавторизованной сессии покажет понятную ошибку.
  Файл истории подменяется целиком только после успешной записи, поэтому расчёт никогда не читает недописанный файл. Сессия Telegram — один файл: пока работает
  `python cli.py bot` с той же `TG_SESSION`, подгрузка может сообщать «database is locked» и повторит попытку через период.
- **Автоподгрузка свечей**: backend докачивает свечи активов из `SYMBOLS` (или из `CANDLES_SYNC_SYMBOLS`) при запуске и затем каждые 5 минут
  (`CANDLES_SYNC_MIN`); качается только хвост, поэтому запрос лёгкий. Актив, по которому идёт ручная загрузка, пропускается. Состояние — в полосе «Сейчас».
- **Индикация расчёта**: пока считается бэктест, вверху бежит полоса, на кнопке «Запустить» крутится спиннер и идёт счётчик секунд, по центру появляется плашка «Считаю… N с», а прежний результат приглушается (но остаётся на месте). При `prefers-reduced-motion` анимация упрощается.
- **Перенос конфига**: вверху панели параметров «⬇ Скачать конфиг» сохраняет все текущие параметры (источник, актив, стратегия, фильтры, тренд,
  депозит, топ-коины, ТФ графика) одним JSON-файлом; «Копировать» кладёт тот же JSON в буфер. «⬆ Загрузить…» принимает файл или вставленный текст и
  сразу применяет его и запускает расчёт. Работает и с «голым» объектом параметров. Неизвестные поля пропускаются (об этом сообщит уведомление), а если
  актива или источника из конфига у вас нет, остаются текущие.
- **Запоминание выбора**: последний источник и актив, а также все параметры и таймфрейм **по каждой связке «источник + актив»**
  хранятся на сервере в базе пользователя (`DB_FILE`). Переживают перезапуск бэкенда, браузера и работают из
  любого браузера. «Сбросить к env» возвращает значения из `.env` для текущей связки.

## Консоль

Запускать из папки `backend/`: `python cli.py <команда>`. Рабочая папка при этом переключается в корень репозитория,
поэтому `history.csv`, `trades.csv`, `data/` и сессии Telegram лежат там же, где и раньше.

```bash
python cli.py backtest history.csv --exchange binanceusdm --symbol BTC/USDT:USDT      # бэктест (флаги как раньше, --help)
python cli.py backtest history.csv --sweep-long          # сетка порогов лонга; --sweep-short — шорта
python cli.py backtest history.csv --sweep-cool --side short
python cli.py backtest history.csv --liq-file history_binance.csv --sweep-liq
python cli.py export history.csv                         # выгрузка канала из TG_CHANNEL_ID (дописывает только новые сообщения)
python cli.py export history_binance.csv --chat 2119980662   # или --chat maverickBinance; --full — заново
python cli.py bot                                        # Telegram-бот (DRY_RUN=true по умолчанию — только лог)
```

Подробности по правилам и флагам бэктеста: `python cli.py backtest --help` и `backend/app/core/entries.py`.

### Правила симуляции (одни и те же в бэктесте, интерфейсе и боте)

- **Лонг**: `Deep Local ≥ LOCAL_MIN` и `Deep Scalp ≥ SCALP_MIN` в `CONFIRM` отчётах подряд. **Шорт**: `Local ≤ SHORT_LOCAL_MAX`
  и `Scalp ≤ SHORT_SCALP_MAX`. Режим `ONLY` оставляет одну метрику.
- Вход по open первой свечи после последнего подтверждающего отчёта; SL / TP — проценты от цены входа. Комиссия берётся с обеих сторон
  (вход на 100% позиции и выходы в сумме на 100%).
- **Тейки частями**: от 1 до 3 уровней, у каждого расстояние от входа (%) и доля позиции (%), доли в сумме 100%. Например
  `TP_LEVELS=3:50,6:30,10:20` — на +3% закрыть 50%, на +6% ещё 30%, на +10% остальные 20%. Задаётся в интерфейсе, в `.env`
  (`TP_LEVELS`; без него один тейк `TP_PCT` на 100%) или в консоли (`--tps 3:50,6:30,10:20`).
- **Безубыток** (`BE_AFTER_TP1`, `--be-after-tp1`, галочка в интерфейсе): после первого тейка стоп переносится в цену входа.
  Нужно минимум 2 тейка. Остаток, закрытый по такому стопу, помечается «БУ».
- Порядок внутри свечи неизвестен, поэтому берётся худшее для результата: сначала проверяется действующий стоп (если в одной
  свече задеты и стоп, и тейк — сработал стоп); затем по порядку исполняются тейки; если при включённом БУ в свече исполнился
  первый тейк и цена коснулась входа — считаем, что возврат был после тейка и остаток закрыт в БУ. При гэпе — по цене открытия.
- Сделка считается прибыльной (для winrate), если суммарный результат всех её частей > 0: тейк на части и потом БУ — это плюс.
- При развороте уже исполненные тейки остаются, остаток закрывается по рынку на open свечи входа новой позиции.
- Одна позиция одновременно: сигнал в ту же сторону игнорируется, в противоположную — **разворот** (закрытие + новая позиция).
- Топ-коины считаются теми же правилами выхода (мульти-TP, БУ, порядок внутри свечи), но отдельно и в долларах; бот их пока не торгует.
- Фильтры входа (только бэктест/интерфейс, бот их пока не использует): остывание метрик, «ликвидации закончились», пауза после стопа.

### Бот и Binance

`EXCHANGE=binanceusdm`, `SYMBOL=BTC/USDT:USDT`. Ключ API: Futures включён, вывод выключен, лучше с привязкой к IP.
Аккаунт должен быть в **One-way** режиме (не Hedge) — иначе `reduceOnly` отклоняется. Обновляйте ccxt (`pip install -U ccxt`):
Binance меняет API условных ордеров. Если SL/TP выставить не удалось — позиция сразу закрывается. `DRY_RUN=false` — реальная торговля.
**Тейки частями и безубыток бот пока не поддерживает** — только один тейк на всю позицию. Если в `.env` заданы несколько тейков
или `BE_AFTER_TP1=true`, бот при запуске остановится с понятным сообщением, а не будет молча торговать не так, как в бэктесте.
