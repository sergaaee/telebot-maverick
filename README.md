# telebot-maverick

Торговый бот по сигналам Telegram-ботов Maverick (метрики Deep Global / Local / Scalp), бэктест и интерактивный интерфейс
для просмотра сделок на графике.

```
backend/     Python: FastAPI-API для интерфейса, движок бэктеста, Telegram-бот и экспорт истории
  app/core/    движок: симуляция сделок (backtest.py), точки входа и фильтры (entries.py), разбор сообщений (signal_parser.py)
  app/         API: config.py (env), data.py (источники и свечи), service.py (запуск бэктеста), state.py, main.py
  tools/       bot.py, trader.py (биржа), export_history.py (выгрузка истории из Telegram)
  tests/       pytest: движок, API, экспорт
  cli.py       консольная точка входа: serve | backtest | export | bot
signalbot/   Telegram-бот сигналов: принимает конфиги (файлом/текстом) и присылает новые сигналы со статистикой конфига (см. signalbot/README.md)
frontend/    React + TypeScript + Vite + lightweight-charts: график, сигналы, TP/SL, статистика
e2e/         проверка интерфейса в настоящем браузере на синтетических данных
```

Пользовательские данные лежат в **корне репозитория** и не коммитятся: `history*.csv` (выгрузки), `data/` (кеш свечей и
`ui_state.json` с вашим выбором), `*.session` (сессии Telegram), `trades.csv`.

> **Деплой на VPS (Docker + nginx):** ветка `server`, инструкция — [DEPLOY.md](DEPLOY.md).

## Пользователи и вход

На сайт входят по логину и паролю. **Регистрации на сайте нет** — пользователей создаёт администратор в консоли сервера:

```bash
cd backend
python cli.py user add ЛОГИН         # пароль спросит; первый пользователь — администратор
python cli.py user list              # passwd / disable / enable / remove / link / unlink / link-code / import-legacy — python cli.py user -h
```

После входа подгружаются последние сохранённые настройки именно этого пользователя (выбор источника и актива, параметры по каждой связке, таймфрейм);
конфиги бота сигналов и привязка Telegram — тоже его. Всё хранится в SQLite (`data/maverick.db`, `DB_FILE`). **Данные рынка общие для всех** (история
сообщений ботов, свечи, активы из «＋ Добавить актив…») — их никто не качает заново. Пароли хранятся хэшем (scrypt), сессия — HttpOnly-cookie
(`SESSION_DAYS`, `COOKIE_SECURE=true` за HTTPS), есть защита от перебора пароля и CSRF. Если до этого пользователь был один (вы), первый
`user add` переносит ваши прежние настройки и конфиги бота в его аккаунт. `AUTH_ENABLED=false` отключает вход (только для локальной разработки).

## Быстрый старт

```bash
# 1. Бэкенд
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # заполнить: источники, активы, параметры стратегии (+ Telegram/биржа для бота)
python cli.py serve               # API на http://127.0.0.1:8000  (python cli.py serve --reload — с автоперезагрузкой)

# 2. Интерфейс (в другом терминале)
cd frontend
cp .env.example .env              # необязательно
npm install
npm run dev                       # http://localhost:5173, /api проксируется на бэкенд
```

Свечи: в интерфейсе кнопка **«Обновить свечи»** (или `python cli.py backtest …`) скачивает их с биржи в `data/`.

## Конфигурация (`backend/.env`)

Все важные значения — в одном файле `backend/.env` (шаблон — `backend/.env.example`). Им пользуются и API, и бэктест, и бот,
поэтому интерфейс и бот не расходятся в параметрах.

| Группа | Переменные |
|---|---|
| Источники метрик | `SOURCES=coinbase,binance`, `SOURCE_<ID>_FILE`, `SOURCE_<ID>_LABEL`, `SOURCE_DEFAULT`, `LIQ_SOURCE`, `LIQ_MAX_AGE_H` |
| Активы и свечи | `EXCHANGE`, `SYMBOLS`, `SYMBOL_DEFAULT`, `CANDLE_TF`, `CACHE_DIR`, `MAX_BARS` |
| Пользователи | `AUTH_ENABLED`, `DB_FILE`, `SESSION_DAYS`, `COOKIE_SECURE`, `SIGNALBOT_USERNAME` |
| Сервер | `HOST`, `PORT`, `CORS_ORIGINS`, `ASSETS_FILE` (`STATE_FILE` — только источник для переноса старых настроек) |
| Стратегия (умолчания) | `SIDE`, `ONLY`, `LOCAL_MIN`, `SCALP_MIN`, `SHORT_LOCAL_MAX`, `SHORT_SCALP_MAX`, `GLOBAL_MIN`, `SHORT_GLOBAL_MAX` (необязательные пороги Deep Global), `CONFIRM`, `TP_PCT` или `TP_LEVELS`, `BE_AFTER_TP1`, `SL_PCT`, `DEPOSIT`, `TRADE_PCT`, `LEVERAGE`, `COMPOUND`, `FEE`, `SLIPPAGE` |

| Пирамидинг и паузы (умолчания) | `PYRAMID_ENABLED`, `PYRAMID_MAX`, `PYRAMID_PCT`, `PYRAMID_GAP_H`, `PYRAMID_MOVE_PCT`, `PYRAMID_MOVE_DIR`, `WEEKEND_NO_ENTRY`, `WEEKEND_CLOSE`, `WEEKDAYS_ONLY` (прежняя общая галочка), `EXIT_LONG_DS`, `EXIT_SHORT_DS`, `FRIDAY_CLOSE_BEFORE_MIN`, `PYRAMID_LEVERAGE`, `LIQUIDATION_SIM`, `MAINT_MARGIN_PCT`, `PYRAMID_AVG`, `SIGNAL_GAP_H`, `SL_HOLD_STRONG` |

Старый формат (`HISTORY_FILE`, `LIQ_FILE`, `SYMBOL`) тоже понимается. Корневой `.env` читается как запасной.

## Интерфейс

- **График** свечей с маркерами входа (▲ лонг / ▼ шорт) и выхода (TP / SL / REV / OPEN), линиями входа, тейка и стопа на время
  сделки и, по желанию, пропущенными сигналами. Клик по сделке на графике или в таблице приближает к ней.
- **Таймфрейм**: «Авто» подбирает под масштаб, либо фиксированный (1m … 1d). Листание и зум подгружают свечи; смена ТФ
  сохраняет вид и выбранную сделку; ← / → — предыдущая/следующая сделка.
- **Параметры**: актив, источник метрик (Coinbase / Binance Maverick) и отдельно источник ликвидаций, сторона, режим «только Local /
  только Scalp / только Global», необязательные пороги Deep Global, пороги, подтверждение, TP/SL, комиссия, проскальзывание, пауза после стопа, фильтры «остывание метрик» и
  «ликвидации закончились», период. У каждого параметра значок **«?»** с описанием, как он работает (тексты — `frontend/src/helpTexts.ts`).
- **Статистика**: итог, число сделок, winrate, profit factor, просадка, средние, серия убытков, время в позиции; разрезы по
  сторонам и половинам истории; результаты по месяцам; кривая капитала; таблица сделок.
- **Активы**: в списке «Актив» — `SYMBOLS` из `.env`, а пункт «＋ Добавить актив…» добавляет новый прямо из интерфейса. Достаточно
  написать `ETH`, `ETHUSDT`, `ETH/USDT` или полный символ. Бэкенд проверяет, что такой бессрочный контракт есть на бирже
  (при опечатке подскажет похожие), запоминает актив в `ASSETS_FILE` и **скачивает свечи в фоне**: интерфейс не блокируется, в
  шапке виден ход загрузки. Когда загрузка закончится (или завершится ошибкой с причиной), придёт уведомление в приложении
  (с кнопкой «Открыть …») и системное уведомление браузера, если вкладка в фоне и вы разрешили их. Уведомление не теряется,
  если страницу перезагрузили или закрыли во время загрузки: оно показывается, пока вы его не закроете. «Обновить свечи» тоже
  работает в фоне. Добавленный из интерфейса актив можно убрать из списка (файл со свечами остаётся на диске).
- **Депозит, доля на сделку, плечо**: размер каждой сделки = текущий баланс × «доля депозита» × плечо (баланс = депозит + закрытые результаты, то есть
  со сложным процентом; если баланс упал до нуля, торговля прекращается). Доходность на объём от плеча не зависит, суммы в $ растут пропорционально.
  Галочка «сложный процент» выключена — простой процент: каждая сделка на одну и ту же сумму (доля от начального депозита × плечо).
  Если плечо × стоп ≥ 100%, показывается предупреждение: на бирже позицию ликвидировали бы раньше стопа, а бэктест ликвидацию не моделирует.
  В статистике — доходность от депозита, просадка в % от пика и **коэффициент Шарпа**: годовой, по дневным доходностям баланса (результат за день /
  баланс на начало дня, дни без сделок = 0, × √365, безрисковая ставка 0). При менее чем двух днях истории или нулевом разбросе показывается «–».
  Топ-коины по-прежнему торгуются фиксированной суммой в $ и в Шарпе не участвуют.
- **Тренд**: чекбокс «торговать только по тренду» оставляет лонги, когда цена выше выбранных EMA (20/50/100/200, можно несколько — цена должна быть по
  нужную сторону от всех), и шорты, когда ниже. EMA считается по закрытым свечам выбранного таймфрейма (по умолчанию 1h) на момент сигнала, без
  заглядывания вперёд; пока свечей меньше периода самой длинной EMA, сделки не открываются. Фильтр относится к основному активу; сигналы для топ-коинов он не
  режет. Отсечённые сигналы считаются в чипе над графиком и в «пропущенных».
- **Топ-коины**: в каждом отчёте есть блок Top Coin — первая строка (`TIA-USD | 10.12`) это топ-коин. Когда основная стратегия
  (по вашим параметрам) подтверждает сигнал, по этой монете в тот же момент открывается сделка в ту же сторону со **своими** настройками
  (тейки частями, безубыток, стоп, размер в $, комиссия, проскальзывание — секция «Топ-коины» в параметрах). Результаты — на отдельной
  вкладке «Топ-коины»: статистика, разрез по монетам, график монеты (клик по сделке или по монете), кривая капитала и список
  пропущенных сигналов с причинами (нет топ-коина в отчёте, нет фьючерса на бирже, значение ниже порога, по монете уже есть позиция…).
  Свечи монет качаются **только на окно «момент сигнала + `TOP_DAYS` суток»** (по умолчанию 3) — кнопкой «Скачать свечи» на вкладке: в
  фоне, с уведомлением; уже скачанные окна повторно не качаются (карта окон `*.windows.json` рядом с кешем). После загрузки сделки
  пересчитываются сами. Если за окно не сработали ни тейк, ни стоп, позиция закрывается по рынку (причина TIME); для свежих сигналов
  окно ещё не закончилось — такие сделки помечены ⏳. Тикер из отчёта сопоставляется с бессрочным USDT-контрактом биржи (`TIA-USD` →
  `TIA/USDT:USDT`, `PEPEUSDT` → `1000PEPE/USDT:USDT`); у монет без фьючерса (например `WBETHUSDT`) сделки не открываются. По монете одна позиция
  одновременно: следующие сигналы, пока она открыта, пропускаются.
- **Текущие метрики и автоподгрузка истории**: в полосе «Сейчас» под шапкой — последние DG / DL / DS каждого бота (DL, DS и DG — если задан его порог — зелёные при условии лонга
  ваших параметров, красные при условии шорта), время отчёта и топ-коин. Сервер сам подгружает новые сообщения обоих ботов из Telegram **при запуске и затем
  каждую минуту** (`HISTORY_SYNC_MIN`, по умолчанию 1; можно задать расписание по минутам часа, например `HISTORY_SYNC_AT=2,32`; сайт и бот не мешают друг другу — сессия Telegram блокируется на время подгрузки); кнопка «Обновить сейчас» запускает подгрузку немедленно. Когда пришли новые сообщения, появляется уведомление с
  кнопкой «Пересчитать» (расчёт не меняется сам, чтобы не сбивать выбранную сделку); свечи для новых отчётов докачиваются кнопкой «Обновить свечи».
  Чаты задаются `SOURCE_<ID>_CHAT` (по умолчанию coinbase → `TG_CHANNEL_ID`, binance → 2119980662). Нужны `TG_API_ID`, `TG_API_HASH` и уже авторизованная сессия
  Telegram: один раз выполните `python cli.py export …` и введите код — сервер сам кода не спрашивает и при неавторизованной сессии покажет понятную ошибку.
  Файл истории подменяется целиком только после успешной записи, поэтому расчёт никогда не читает недописанный файл. Сессия Telegram — один файл: пока работает
  `python cli.py bot` с той же `TG_SESSION`, подгрузка может сообщать «database is locked» и повторит попытку через период.
- **Автоподгрузка свечей**: backend докачивает свечи активов из `SYMBOLS` (или из `CANDLES_SYNC_SYMBOLS`) при запуске и затем каждые 5 минут
  (`CANDLES_SYNC_MIN`); качается только хвост, поэтому запрос лёгкий. Актив, по которому идёт ручная загрузка, пропускается. Состояние — в полосе «Сейчас».
- **Индикация расчёта**: пока считается бэктест, вверху бежит полоса, на кнопке «Запустить» крутится спиннер и идёт счётчик секунд, по центру появляется плашка «Считаю… N с», а прежний результат приглушается (но остаётся на месте). При `prefers-reduced-motion` анимация упрощается.
- **Перенос конфига**: вверху панели параметров «⬇ Скачать конфиг» сохраняет все текущие параметры (источник, актив, стратегия, фильтры, тренд,
  депозит, топ-коины, ТФ графика) одним JSON-файлом; «Копировать» кладёт тот же JSON в буфер. «⬆ Загрузить…» принимает файл или вставленный текст и
  сразу применяет его и запускает расчёт. Работает и с «голым» объектом параметров. Неизвестные поля пропускаются (об этом сообщит уведомление), а если
  актива или источника из конфига у вас нет, остаются текущие.
- **Запоминание выбора**: последний источник и актив, а также все параметры и таймфрейм **по каждой связке «источник + актив»**
  хранятся на сервере в базе пользователя (`DB_FILE`). Переживают перезапуск бэкенда, браузера и работают из
  любого браузера. «Сбросить к env» возвращает значения из `.env` для текущей связки.

## Консоль

Запускать из папки `backend/`: `python cli.py <команда>`. Рабочая папка при этом переключается в корень репозитория,
поэтому `history.csv`, `trades.csv`, `data/` и сессии Telegram лежат там же, где и раньше.

```bash
python cli.py backtest history.csv --exchange binanceusdm --symbol BTC/USDT:USDT      # бэктест (флаги как раньше, --help)
python cli.py backtest history.csv --sweep-long          # сетка порогов лонга; --sweep-short — шорта
python cli.py backtest history.csv --sweep-cool --side short
python cli.py backtest history.csv --liq-file history_binance.csv --sweep-liq
python cli.py export history.csv                         # выгрузка канала из TG_CHANNEL_ID (дописывает только новые сообщения)
python cli.py export history_binance.csv --chat 2119980662   # или --chat maverickBinance; --full — заново
python cli.py bot                                        # Telegram-бот (DRY_RUN=true по умолчанию — только лог)
```

Подробности по правилам и флагам бэктеста: `python cli.py backtest --help` и `backend/app/core/entries.py`.

### Правила симуляции (одни и те же в бэктесте, интерфейсе и боте)

- **Лонг**: `Deep Local ≥ LOCAL_MIN` и `Deep Scalp ≥ SCALP_MIN` в `CONFIRM` отчётах подряд. **Шорт**: `Local ≤ SHORT_LOCAL_MAX`
  и `Scalp ≤ SHORT_SCALP_MAX`. Режим `ONLY` (`local` / `scalp` / `global`) оставляет одну метрику.
- **Deep Global** (необязательно): при заданном `GLOBAL_MIN` лонг требует ещё и `Global ≥ GLOBAL_MIN`, при `SHORT_GLOBAL_MAX` шорт — `Global ≤ SHORT_GLOBAL_MAX`.
  Пусто — Global не учитывается (как раньше). Если порог задан, а в отчёте Global нет — условие не выполнено. Global также можно выбрать метрикой фильтра остывания
  и режимом «только Global» (тогда пороги Global обязательны). Старые конфиги и профили без этих полей остаются с выключенным Global, даже если в `.env` заданы `GLOBAL_MIN` / `SHORT_GLOBAL_MAX`.
- Вход по open первой свечи после последнего подтверждающего отчёта; SL / TP — проценты от цены входа. Комиссия берётся с обеих сторон
  (вход на 100% позиции и выходы в сумме на 100%).
- **Тейки частями**: от 1 до 3 уровней, у каждого расстояние от входа (%) и доля позиции (%), доли в сумме 100%. Например
  `TP_LEVELS=3:50,6:30,10:20` — на +3% закрыть 50%, на +6% ещё 30%, на +10% остальные 20%. Задаётся в интерфейсе, в `.env`
  (`TP_LEVELS`; без него один тейк `TP_PCT` на 100%) или в консоли (`--tps 3:50,6:30,10:20`).
- **Безубыток** (`BE_AFTER_TP1`, `--be-after-tp1`, галочка в интерфейсе): после первого тейка стоп переносится в цену входа.
  Нужно минимум 2 тейка. Остаток, закрытый по такому стопу, помечается «БУ».
- Порядок внутри свечи неизвестен, поэтому берётся худшее для результата: сначала проверяется действующий стоп (если в одной
  свече задеты и стоп, и тейк — сработал стоп); затем по порядку исполняются тейки; если при включённом БУ в свече исполнился
  первый тейк и цена коснулась входа — считаем, что возврат был после тейка и остаток закрыт в БУ. При гэпе — по цене открытия.
- Сделка считается прибыльной (для winrate), если суммарный результат всех её частей > 0: тейк на части и потом БУ — это плюс.
- При развороте уже исполненные тейки остаются, остаток закрывается по рынку на open свечи входа новой позиции.
- Одна позиция одновременно: сигнал в ту же сторону игнорируется, в противоположную — **разворот** (закрытие + новая позиция).
- Топ-коины считаются теми же правилами выхода (мульти-TP, БУ, порядок внутри свечи), но отдельно и в долларах; бот их пока не торгует.
- **Пирамидинг** (раздел «Пирамидинг и паузы»): если включён и приходит новый подтверждённый сигнал (все условия и фильтры, как для обычного входа) в ту же
  сторону, пока позиция открыта, делается **добор**: максимум `PYRAMID_MAX` раз за позицию, размером `PYRAMID_PCT`% депозита (первый вход — `TRADE_PCT`%; сумма не может превысить 100%),
  не чаще, чем раз в «паузу между доборами» и — если задано «движение от последнего входа» (`PYRAMID_MOVE_PCT`, `PYRAMID_MOVE_DIR`: any / favor / against) — только когда цена ушла от цены
  последнего входа не меньше чем на этот % (оба условия — время и цена — должны выполняться; 0 — не проверять; в боте для свежих сигналов проверка идёт по текущей цене биржи). Каждый добор — отдельная «нога» со своей ценой входа, тейками, безубытком и стопом; ноги закрываются независимо. Противоположный
  сигнал закрывает все ноги и разворачивает позицию. **«Пирамидинг усредняет позу»** (`PYRAMID_AVG`): доборы входят в ОДНУ позицию — после каждого добора считается новая средняя цена
  входа (по количеству), и от неё заново считаются стоп, безубыток и ещё не исполненные тейки (исполненные остаются; остаток делится между оставшимися тейками в прежних пропорциях).
  Усреднённая позиция — одна сделка (в таблице метка ×N, на графике доборы отмечены стрелками `+1`, `+2`; линии TP/SL на графике показывают итоговые уровни), размер сделки = вход + доборы
  в % депозита. Без доборов результат совпадает с обычной сделкой. В статистике каждая нога — отдельная сделка (winrate и PF считаются по ногам), отдельно показаны «позиций / доборов».
- **Паузы**: «пауза между сигналами» — минимум часов между открытиями позиций (новый вход после закрытия предыдущей или разворот; отсчёт от открытия предыдущей позиции);
  «пауза между доборами» — минимум часов после предыдущей ноги; «пауза после стопа» работает как раньше. Пропущенные сигналы получают причину (список в статистике).
- **«Не ставить SL, пока метрики сильны»**: пока последний отчёт всё ещё удовлетворяет условию входа (лонг: DL и DS (и DG, если задан порог) не ниже порогов лонга; шорт: не выше порогов шорта; в режиме «только Local/Scalp/Global» —
  один показатель), стоп-лосс не действует. Как только метрики остыли, стоп работает с этой свечи (если цена уже за ним — выход по её open, убыток может быть больше заданного стопа).
  Стоп в безубытке после TP1 не отключается. **Риск:** пока метрики сильны, убыток по позиции ничем не ограничен.
- **Обратная совместимость**: все новые возможности по умолчанию выключены. Конфиги и профили, сохранённые раньше (без этих полей), считаются так же, как и считались; бот и интерфейс
  при загрузке старого конфига выключают новые возможности, даже если в `.env` заданы другие умолчания.
- Фильтры входа (только бэктест/интерфейс, бот их пока не использует): остывание метрик, «ликвидации закончились», пауза после стопа.

### Бот и Binance

`EXCHANGE=binanceusdm`, `SYMBOL=BTC/USDT:USDT`. Ключ API: Futures включён, вывод выключен, лучше с привязкой к IP.

## Плечо, ликвидация и реальная просадка

- **Плечо доборов** (`PYRAMID_LEVERAGE`, пусто — как у первой ноги): размер добора = доля депозита × это плечо; маржа от плеча не зависит. У усреднённой позиции веса — объём (доля × плечо).
- **Моделировать ликвидацию** (`LIQUIDATION_SIM`, по умолчанию выключено — как раньше): цена ликвидации ноги — вход × (1 − 1/плечо + `MAINT_MARGIN_PCT`) для лонга, зеркально для шорта;
  маржа изолированная, у каждой ноги своё плечо, у усреднённой позиции — эффективное плечо (общий объём / общая маржа). Касание закрывает остаток ноги с потерей **всей** её маржи
  (−100%/плечо от объёма, метка `LIQ`). Если стоп ближе к входу, чем ликвидация, раньше срабатывает он; если дальше или снят режимом «не ставить SL, пока метрики сильны» — ликвидация.
  Упрощения: без ступеней поддерживающей маржи по объёму, без фандинга; гэпы — по цене банкротства (потеря маржи не больше 100%).
- **Реальная просадка** (карточка в статистике, строка «с открытыми позициями» в боте): капитал = депозит + закрытые результаты + нереализованный результат открытых ног по худшей цене свечи.
  Показывает, насколько глубоко счёт проседал внутри сделок — с учётом плеча, размера и одновременных ног пирамидинга. Обычная «Макс. просадка» считается только по закрытым сделкам.
  Приближённо: свечи группируются в блоки (до ~15 000), усреднённая позиция берётся полным размером с первой свечи (консервативно).

## «Ждёт подтверждения»

Когда серия подтверждена (нужное число отчётов подряд), а вход ещё держит фильтр, интерфейс и бот говорят об этом, а не молчат:

- **На графике** фиолетовые точки у отчётов, где серия есть, но вход не разрешён (переключатель «ждут подтверждения»); у самого свежего подпись «ждёт L/S». Над графиком — баннер «Готов к ЛОНГУ/ШОРТУ, ждёт подтверждения»
  с перечнем условий и цифрами: **откат метрики** (сколько нужно и сколько есть), **ликвидации** (всплеск был/нет, текущее значение и нужный предел), **тренд** (какая EMA и таймфрейм).
- **В боте** при появлении такого состояния приходит сообщение «⏳ Готов к ЛОНГ, ждёт подтверждения» с теми же строками; повторно — только если набор ожидаемых условий поменялся.
  Если серия прервалась без входа, приходит «⌛ Ожидание отменено». Когда вход состоялся, приходит обычное сообщение о входе. Для конфигов, созданных до этой функции, первое состояние фиксируется молча.
- Если по стороне уже открыта позиция и пирамидинг выключен, ожидание не показывается (сигнал всё равно был бы пропущен); при включённом пирамидинге пишется «готов к добору».

## Выходные: две опции вместо одной галочки

Прежняя галочка «торговать только в будни» разделена на две независимые опции (обе по умолчанию выключены — как раньше):

- **«Не открывать позиции по сигналам в выходные»** (`WEEKEND_NO_ENTRY`). **Вход** (в том числе добор и разворот) разрешён с открытия Токио в понедельник (09:00 JST = 00:00 UTC) до закрытия Нью-Йорка в пятницу
  (17:00 по Нью-Йорку: 21:00 UTC летом, 22:00 UTC зимой; переход на летнее время США учтён в `core/tradingweek.py`). Сигналы в остальное время — пятница после закрытия, суббота, воскресенье — пропускаются
  с причиной «выходные: вне торгового окна»; лимитный ордер на вход живёт не дольше закрытия пятницы. Уже открытая позиция при этом **не закрывается**.
- **«Закрывать позиции перед выходными»** (`WEEKEND_CLOSE`). Если позиция к закрытию пятницы всё ещё открыта, она закрывается по цене открытия свечи закрытия (метка `WKND`); TP, SL, БУ, разворот и ликвидация срабатывают раньше.
  Позиция, открытая в выходные (если вход в выходные разрешён), закрывается в ближайшую пятницу. `FRIDAY_CLOSE_BEFORE_MIN` сдвигает закрытие недели на столько минут раньше (и запрет на вход, если он включён).
- Старые конфиги и `WEEKDAYS_ONLY=true` работают как раньше: прежняя общая галочка включает **обе** опции сразу (если новые явно не заданы). При загрузке старого конфига в интерфейс обе опции включаются по его галочке.
- Опции относятся к основной стратегии, сделки по топ-коинам не затрагиваются. В боте пропускаются входы вне окна, закрытие в пятницу приходит как «📅 Закрытие к концу недели» (и закрывает позицию на бирже в режиме «управлять»).
- В статистике есть таблица **«Будни и выходные»**: сколько сделок закончилось тейком / безубытком / стопом / разворотом / ликвидацией / закрытием в пятницу / по DS в будни и в выходные (штуки и процент от сделок группы),
  winrate, итог и число входов. Причина считается по моменту выхода; закрытие пятницы — будний выход. Таблица есть и при выключенных опциях — так видно, что происходило в выходные, прежде чем их отключать.

## Закрытие по DS (отдельные пороги выхода)

Кроме стопа, тейков и разворота позицию можно закрывать по **DS (Scalp)** нового отчёта — с порогами выхода, которые **не зависят от порогов входа**:

- **«Закрыть лонг при Scalp ≤»** (`exit_long_ds`, `EXIT_LONG_DS`) — когда приходит новый отчёт с DS не выше значения, лонг закрывается по рынку.
- **«Закрыть шорт при Scalp ≥»** (`exit_short_ds`, `EXIT_SHORT_DS`) — когда приходит новый отчёт с DS не ниже значения, шорт закрывается по рынку.
- Например: вход в лонг от DS ≥ 1, выход из лонга при DS ≤ 1.05; вход в шорт от DS ≤ 2, выход из шорта при DS ≥ 1.95. Пусто — не закрывать по DS (по умолчанию).
- Расчёт: решение принимается на свече, где пришёл отчёт, цена выхода — open этой свечи с проскальзыванием, метка сделки **`DS`**. Отчёт, по которому открыта позиция, не считается; все ноги пирамидинга и усреднённая позиция закрываются целиком.
  Стоп, тейки и закрытие перед выходными срабатывают раньше, если цена дошла до них до отчёта.
- Если порог выхода не строже порога входа (например, выход лонга при DS ≤ 1.05, а вход от DS ≥ 1.0), в результате будет предупреждение: при DS между порогами лонг закроется на ближайшем же отчёте.
- В боте закрытие по DS приходит как «📉 Закрытие по DS» и в режиме «управлять» закрывает позицию на бирже (запись `close_ds` в журнале). Для сигналов, пришедших позже последней свечи, бот пока не знает о таком выходе — это длится до следующей свечи (около минуты).

## Статистика по дням недели и сессиям

В правой колонке — блок «По дням и сессиям» (переключатель «по входу» / «по выходу»): для каждого дня недели (пн…вс, UTC) и каждой сессии — число сделок, доля тейков (TP%) и стопов (SL%), winrate, profit factor и итог;
остальные причины выхода (безубыток, разворот, ликвидация, закрытие в пятницу, открыто) видны во всплывающей подсказке строки. Сессии без пересечений и без перехода на летнее время:
**Азия (Токио) 00:00–08:00, Европа (Лондон) 08:00–13:00, США (Нью-Йорк) 13:00–21:00, вечер/ночь 21:00–24:00 UTC**. Ноги пирамидинга считаются отдельными сделками, топ-коины не входят.
Группы с малым числом сделок статистически ненадёжны — смотрите на n.

## Срок удержания позиций

Блок «Сколько держатся позиции» в статистике: медиана, среднее и p90 срока (от входа до закрытия) — по всем закрытым сделкам, отдельно у плюсовых и минусовых и по причинам выхода (тейк, стоп, безубыток…);
распределение по группам срока (< 1 ч, 1–4 ч, 4–12 ч, 12–24 ч, 1–2 сут, 2–4 сут, > 4 сут) с полосой доли сделок, TP%, SL%, winrate, PF и итогом; и корреляция Пирсона между логарифмом срока
и результатом сделки в % («чем дольше держим, тем лучше/хуже»). Открытые на конец данных позиции не учитываются (их срок ещё неизвестен), число таких указано под таблицей. Это описание прошлых сделок, не правило входа.

## Мониторинг позиций, автомод и торговля на Hyperliquid, Bybit и Upscale

Ссылка «📡 Мониторинг» в шапке открывает **отдельную страницу** `/monitor.html` (свой адрес, шапка и раскладка; бэктест на ней не загружается и от введённых там параметров не зависит; вход общий).

- **Список стратегий** — все конфиги, которые вы отправляли боту: статус (в лонге/шорте, ждёт подтверждения, на паузе, ошибка), результат открытой позиции, переключатели автомода, «Пауза/Возобновить».
- **«Подробнее»** раскрывает под строкой вкладки: *Позиция* (по ногам: вход, стоп или БУ и запас, тейки, оценка ликвидации, метрики на входе, результат), *История*, *Статистика*, *Параметры*, *Журнал*;
  там же: переименовать, скачать конфиг, удалить. Пауза выключает автомод; возобновление пересчитывает конфиг с нуля (сигналы, пропущенные на паузе, не накапливаются).
- Позиции в списке — **расчёт стратегии по свечам и отчётам Binance**, а не позиции на бирже. Блоки **«Биржа»** (отдельно для Hyperliquid и для Bybit) показывают подключённый счёт как его видит биржа: кто подключён (адреса маскируются), капитал и маржа,
  реальные позиции, открытые ордера, последние исполнения; там же «Отключить счёт».
- **Автомод** — две независимые галочки у каждого конфига (выключены по умолчанию, включение с подтверждением): «открывать по сигналу» (вход и добор — рыночным ордером со стопом и тейками) и «управлять позицией»
  (стоп в БУ после TP1, закрытие по развороту и к концу недели). «Выключить автомод везде» гасит всё разом. Действия выполняет бот (signalbot).
- **Тестовая позиция по BTC**: маржа 1 $ (потолок 5 $); минимальный ордер Hyperliquid 10 $ объёма, поэтому плечо подбирается автоматически (10×). Подтверждение обязательно; закрывается кнопкой «Закрыть тестовую».

### Две биржи и настройки конфига под каждую
Торговать можно на **Hyperliquid**, на **Bybit** (только **USDT-фьючерсы**: бессрочные linear-контракты; спот, опционы и инверсные контракты не поддерживаются) и на **Upscale** (проп-трейдинг, см. ниже). У пользователя может быть подключён счёт на каждой бирже сразу;
у каждого конфига — **свои переключатели автомода на каждой бирже** («открывать», «управлять», база размера входа): один конфиг может торговать и там и там. Включён автомод только там, где вы его включили; без подключённого счёта на этой бирже — симуляция.

**Свои настройки конфига для биржи** (поверх параметров конфига; пусто — «как в конфиге»): доля депозита и плечо входа, доля и плечо добора, вход лимитным ордером (`entry_limit_pct` — 0 значит «по рынку» даже если в конфиге лимитка,
`entry_limit_dir` — на откат / по ходу, `entry_limit_ttl_h` — сколько живёт ордер). Где менять: на сайте — «Свои настройки по биржам» в строке конфига; в боте — `/ex № hl|bybit|upscale ключ=значение …`
(`/ex 3 bybit trade_pct=5 leverage=3`, `-` вместо значения убирает настройку, `reset` — все) и кнопки «📐 Размер» / «🏦 Настройки по биржам» в карточке. Настройки действуют на **новые входы на этой бирже**.
**Что общее и не настраивается по биржам:** условия сигналов и правила выхода (стоп, тейки, безубыток, закрытие по развороту и к концу недели) берутся из конфига, как и расчёт стратегии, статистика и портфель — они считаются по параметрам конфига,
а не по настройкам биржи. Отличающийся размер или вход лимиткой на бирже — это «исполнение» того же сигнала, поэтому реальный результат на бирже может отличаться от расчёта. Ожидающие лимитки, повторы неудавшегося входа и «догнать сигнал» ведутся по каждой бирже отдельно;
«СТОП ВСЁ» закрывает позиции и снимает ордера на всех подключённых биржах, отключение счёта выключает автомод только на этой бирже.

### Подключение счёта Upscale (проп-трейдинг, только через Telegram-бота)
[Upscale](https://docs.upscale.trade/developers) — платформа проп-трейдинга: у пользователя несколько счетов (демо, платный челлендж / фондированный, турнирный), торговля идёт по личному API-ключу. Адаптер написан по публичной документации (`backend/app/upscale.py`).
1. В приложении Upscale создайте **личный API-ключ** (`usk_…`, показывается один раз) и включите **торговлю по API** у нужного счёта (она включается у каждого счёта отдельно). Ключом принимаются только торговые и справочные операции из документации — **вывода средств среди них нет**,
   поэтому проверять права ключа не нужно (в отличие от Bybit); подписи запросов тоже нет — это обычный bearer-токен.
2. В боте: `/upscale` → «Подключить Upscale» → пришлите ключ. Сообщение с ключом удаляется сразу. Бот проверяет ключ запросом списка счетов и показывает счета, на которых можно торговать (статус `active`, API включён). Выбор — кнопкой: **демо-счёт подключается сразу, платный и турнирный — после подтверждения**.
   Ключ шифруется (как у остальных бирж) и сохраняется вместе с идентификатором счёта; тип счёта виден в блоке биржи. Сменить счёт — отключить и подключить заново.
3. **Платный счёт: правила просадки действуют и при торговле ботом** (лимиты дневной / общей просадки, фазы) — серия убытков или автомод «без стопа» может провалить счёт. Начните с демо-счёта; бот это подчёркивает при подключении.
4. Как исполняется: вход — ордер `market` (`amount` — котируемая сумма = маржа вместе с комиссией и спредом, `leverage` — плечо, поэтому фактический объём чуть меньше расчётного); лимитный вход — ордер `limit`; стоп и тейки — отдельные ордера `stop` / `take` с привязкой к позиции (размер — доля этого входа);
   закрытие по рынку — ордер `take` с нулевой ценой; перестановка стопа — снять старые стопы позиции и поставить новый; «СТОП ВСЁ» — один запрос закрытия всего на счёте. Позиции на Upscale хранятся по направлениям, доборы увеличивают позицию того же направления.
   **Плечо:** максимум зависит от рынка, типа счёта и его фазы (например, 5× на платном счёте). Если плечо конфига выше, биржа отвечает `invalid_leverage` с границами; бот повторяет ордер один раз с ближайшим допустимым плечом и **тем же объёмом сделки** — маржи уходит больше (при плече 5× вместо 10× — вдвое), о чём приходит сообщение. Границы запоминаются на 10 минут. Своё плечо для биржи (и меньший объём) — `/ex № upscale leverage=…`.
   Символ стратегии «BTC/USDT:USDT» превращается в рынок с базовым активом BTC; нет такого рынка у счёта (или он на паузе / только закрытие) — понятная ошибка, а не молчание. Идемпотентность: у каждого запроса записи свой `x-idempotency-key`, повтор после сбоя сети не создаёт второй ордер.
5. Лимиты ключа — 60 запросов в минуту на чтение и на запись (10 в секунду): бот кеширует рынки на 30 секунд, при ответе 429 ждёт `Retry-After`. Свободный баланс Upscale отдаёт не одним числом, поэтому в блоке счёта его нет, а достаточность маржи проверяет сама биржа (ошибка `insufficient_balance` показывается понятным текстом).
   Минимальный объём ордера в документации не указан: для тестовой позиции берётся `UPSCALE_MIN_NOTIONAL` (10 $ по умолчанию), остальное проверяет биржа.
6. **Код Upscale проверен только на имитации API (тесты) и по документации — на живом Upscale он не запускался.** Особенно это касается: нескольких стоп / тейк ордеров на одну позицию, формата страницы истории позиций, поведения лимитных ордеров. Сначала прогоните его на демо-счёте: тестовая позиция $1 (`/monitor` → Upscale → Тест), затем вход по сигналу.

### Подключение счёта Bybit (только через Telegram-бота, только USDT-фьючерсы)
1. Создайте API-ключ на Bybit (профиль → API → Create New Key) с правом только на **торговлю контрактами** (Orders, Positions) и **без права вывода средств** (Withdraw). Лучше привязать ключ к IP сервера бота.
   Для проверки без денег есть **тестовая сеть** (testnet.bybit.com, ключ создаётся там) и **демо-торговля** (Demo Trading на боевом аккаунте, виртуальные деньги).
2. В боте: `/bybit` → «Подключить» (тестовая сеть / демо-торговля / боевая — боевая с отдельным подтверждением) → пришлите **API-ключ**, затем **секрет** (или одним сообщением «ключ секрет»). Сообщения с ключом и секретом бот сразу удаляет.
3. Бот проверяет формат, спрашивает у биржи права ключа (`/v5/user/query-api`) и **не принимает** ключ с правом вывода, ключ только для чтения и ключ без права торговли контрактами; затем проверяет доступ к счёту, сохраняет секрет **зашифрованным** (как у Hyperliquid) и пишет капитал.
   Если биржа не вернула права ключа, ключ тоже не принимается (аварийный обход для администратора — `BYBIT_SKIP_PERM_CHECK=true`; в демо-режиме проверка прав необязательна).
4. Режим позиции — односторонний (one-way), маржа изолированная, где аккаунт это допускает (в Unified Trading Account режим маржи задаётся на уровне аккаунта — биржа может отклонить смену, это не мешает); символ `BTC/USDT:USDT` остаётся как есть. Баланс берётся в USDT.
   Минимальный ордер — 5 $ объёма и минимальное количество монеты по правилам биржи (у BTC — 0.001, то есть порядка сотни долларов объёма; бот проверяет перед отправкой и при слишком малом объёме пишет понятную ошибку с минимумом, а не падает).
   Тестовая позиция $1 на Bybit поэтому поднимает маржу до 5 $ (плечо не выше 25–50×), чтобы пройти минимум; тейки, которые на малой позиции меньше минимального количества, сливаются в соседний, позиция из-за них не закрывается.
5. **Код Bybit проверен только на имитации биржи (тесты) — на живой Bybit он не запускался.** Особенно это касается условных ордеров (стоп/тейк), настроек плеча и режима маржи, чтения прав ключа. Сначала прогоните его в тестовой сети или в демо: тестовая позиция $1 (кнопка с выбором биржи на странице мониторинга, `/monitor` → «Bybit» → «Тест»), затем вход по сигналу.

### Несколько аккаунтов Hyperliquid
Аккаунтов **Hyperliquid** можно подключить несколько (по умолчанию до 3; число задаёт `HL_MAX_ACCOUNTS`, 1…10): `/hl` — первый, `/hl 2`, `/hl 3` … — дополнительные. Для остальной системы каждый аккаунт — **отдельная «биржа»**
(в интерфейсе «Hyperliquid», «Hyperliquid 2» …): свой счёт, свои переключатели «открывать» / «управлять» и база размера в каждом конфиге, свои размер и лимитный вход (`/ex № hl2 trade_pct=5 leverage=3`),
свои ожидающие входы и повторы, своя тестовая позиция и свой блок на странице мониторинга. Сигналы и правила выхода (стоп, тейки, БУ) общие — из конфига. По сигналу бот входит на каждом аккаунте, где включено «открывать», со своим размером;
«СТОП ВСЁ» закрывает позиции на всех. Один и тот же основной кошелёк в двух слотах (в одной сети) бот не примет — иначе по сигналу открылись бы две одинаковые позиции на одном счёте. Отключение одного аккаунта не трогает остальные.
Bybit и Upscale по-прежнему — по одному счёту. Дополнительные аккаунты показываются в карточках и на странице, только пока подключены (или если для них что-то настроено).

### Подключение счёта Hyperliquid (только через Telegram-бота)
1. Аккаунт сайта должен быть **связан с Telegram** (меню пользователя → «Привязать Telegram», `/link КОД`): без этого бот не отвечает ни на что, кроме `/start`, `/help` и `/link`.
2. В боте: `/hl` (второй аккаунт — `/hl 2`) → «Подключить» (тестовая сеть; боевая — с отдельным подтверждением) → пришлите **адрес основного кошелька**, затем **ключ API-кошелька** (Hyperliquid → More → API: он умеет торговать, но не выводить средства).
   Можно и одним сообщением «адрес ключ». **Ключ основного кошелька бот не примет.**
3. Бот проверяет данные (формат; ключ принадлежит именно API-кошельку, подтверждённому для этого адреса; счёт отвечает), **удаляет ваши сообщения с адресом и ключом из чата** (даже при ошибке),
   сохраняет ключ в базе **зашифрованным** (Fernet, мастер-ключ `SECRET_KEY` или файл `secret.key` рядом с базой) и пишет, что подключено. На сайте счёт сразу виден в блоке «Биржа». Отключить — на сайте или в боте.
4. Автомод после подключения остаётся **выключенным** у всех конфигов — включайте вручную. Счёт у каждого пользователя свой; без счёта (или при `TRADE_EXCHANGE=dry-run`) — симуляция: действия пишутся в журнал, ордера не отправляются.

Как исполняется на бирже: плечо — изолированная маржа, вход по рынку, стоп — триггерный reduce-only, тейки — reduce-only лимитки; перестановка стопа = снять старый и поставить новый; если после входа стоп/тейки не встали,
позиция сразу закрывается по рынку. Символ `BTC/USDT:USDT` → `BTC/USDC:USDC`. Предохранитель `TRADE_MAX_USD` (50 000 $ объёма на ордер по умолчанию; если в вашем `.env` стоит прежнее значение, например 5000, поменяйте его там — значение из `.env` важнее умолчания).

**Безопасность автоторговли.**
- *Сверка с биржей.* Перед каждым входом/добором бот смотрит реальные позиции: если по активу уже есть позиция в ту же сторону — вход пропускается (запись в журнал и сообщение), если в обратную — она сначала закрывается (разворот), добор без позиции не выполняется; биржа не отвечает — ордер не отправляется. Закрытие по развороту/концу недели не трогает позицию в другую сторону.
- *СТОП ВСЁ.* Кнопка на странице мониторинга, `/panic` и кнопка в `/monitor`: автомод выключается у всех конфигов, все позиции закрываются по рынку, все ордера снимаются; ошибки по отдельным позициям не прерывают остальное и показываются в отчёте.
- *Пульс и сторож.* Бот пишет в базу, что жив и что циклы идут; страница мониторинга показывает плашку при сбое, а сторож (в backend при `SIGNALBOT_TOKEN` или `python cli.py watchdog`) пишет владельцам автомода в Telegram — один раз за сбой и «снова работает».

**Вход лимиткой.** Вместо входа по рынку после подтверждённого сигнала можно входить ордером на X % движения цены от цены сигнала: параметры «Вход лимиткой, % движения цены» (0 — по рынку), «Куда ставить» (`pullback` — на откат: лонг ниже, шорт выше; `breakout` — по ходу: лонг выше, шорт ниже) и «Ордер живёт» (часы), в конфигах и в `.env` (`ENTRY_LIMIT_PCT/DIR/TTL_H`). **В расчёте:** цена сигнала — open свечи входа; откат исполняется по уровню (или по open, если свеча открылась за ним), вход по ходу — при касании уровня с проскальзыванием; не исполнился за срок — сигнал пропущен (видно в причинах пропуска); повторный сигнал той же стороны, пока ордер стоит, игнорируется, обратный — отменяет ордер; в свече исполнения тейки не засчитываются (порядок внутри свечи неизвестен), стоп — засчитывается; стоп и тейки от цены исполнения; по умолчанию лимиткой входит только первая нога, а доборы пирамидинга идут по рынку (см. «Доборы лимиткой» ниже); комиссия как у рыночного входа. **В автомоде:** «на откат» — настоящий лимитный ордер на бирже (цена от текущей в момент, когда бот увидел сигнал), после исполнения бот ставит стоп и тейки от реальной цены входа; «по ходу» — бот каждый цикл (≈ минута) проверяет цену и при касании уровня входит по рынку. Ордер живёт заданное время, затем снимается; снимается и при обратном сигнале, паузе или выключении автомода, а СТОП ВСЁ снимает всё. Частично исполненный ордер при отмене защищается стопом и тейками на набранный объём. Ожидающие входы хранятся в базе и переживают перезапуск бота; на странице мониторинга и в карточке бота видно, что вход ждёт. Если счёт не подключён, в чат приходит только «поставил бы лимитку».

**Доборы лимиткой.** Опция «доборы пирамидинга тоже лимиткой» (`entry_limit_adds`, `ENTRY_LIMIT_ADDS`, по умолчанию выключена; нужны включённые пирамидинг и вход лимиткой) заставляет доборы входить так же, как первая нога: ордером на тот же X % от цены сигнала ДОБОРА, с тем же направлением и сроком жизни. **В расчёте:** ордер стоит, пока не исполнится или не истечёт срок; повторные сигналы добора той же стороны за это время пропускаются («лимитка добора уже стоит»), обратный сигнал отменяет ордер, а если позиция закрылась раньше (стоп, тейк, закрытие перед выходными, закрытие по DS) — добор отменяется («позиция закрыта до исполнения лимитки добора»). Максимум доборов и пауза между ними проверяются при постановке ордера, а засчитываются при исполнении. Исполненный добор — отдельная нога (или добор в усреднённую позицию) с входом по цене лимитки; в сделке есть `limit.add`; в свече исполнения тейки добора не засчитываются. Если данные кончились раньше исполнения, сигнал считается ожидающим («лимитка добора ждёт исполнения»). **В автомоде:** на бирже ставится лимитка добора (или бот ждёт цену до уровня и добирает по рынку — для «по ходу»); стоп и тейки встают после исполнения **только на добавленный объём** и от цены исполнения добора — как у добора по рынку. Объём берётся из состояния ордера на бирже; если биржа его не отдаёт (Upscale), — как прирост позиции с момента постановки ордера (приближённо: тейки, исполнившиеся за это время, уменьшают прирост). Пока лимитка добора ждёт, позиция должна оставаться открытой: если её не стало, ордер снимается. Лимитка добора хранится в базе вместе с ожидающими входами (в карточке и на странице: «ждёт добор»). Размер и лимитный вход можно задать для биржи отдельно (`/ex`) — они действуют и на доборы. **Код проверен на имитации биржи, на живой бирже не запускался** — проверьте сначала в тестовой сети.

**Фандинг в симуляции.** Параметры «Фандинг, % годовых», «Период списания» (1/2/4/8/12/24 ч) и «Кто платит» (по знаку ставки: при положительной лонг платит, шорт получает; либо платят обе стороны) — в панели параметров, в конфигах и в `.env` (`FUNDING_APR`, `FUNDING_PERIOD_H`, `FUNDING_MODE`). За каждый момент списания (кратный периоду от 00:00 UTC), который позиция «пережила», списывается ставка/год × период/8760 от доли объёма, оставшейся в позиции (закрытые тейками части не платят; у усреднённой позиции — только вошедшие доборы). Учитывается везде, где считается прибыль: итог и кривая капитала, просадка, статистика, топ-коины, пирамидинг, Монте-Карло, walk-forward, портфель, позиции в мониторинге и в боте; в таблице сделок и CSV есть колонка «фандинг $». Ставка в симуляции постоянная (реальная меняется каждый период); по умолчанию выключено, у старых конфигов поля нет — фандинг выключен. Консольный `cli.py backtest` фандинг не учитывает.

**Догнать свежий сигнал.** Обычно при включении автомода бот ждёт СЛЕДУЮЩИЙ сигнал: по пришедшему до этого он не входит (в том числе по только что добавленному конфигу). У конфига можно включить «догнать свежий сигнал» (сайт — строка под размером входа, бот — кнопка «⏩ Догнать сигнал» и `/catchup № on|off [минут] [%]`): при включении автомода «открывать» (или самой опции, если автомод уже включён) бот один раз входит по последнему сигналу, если он не старше N минут (по умолчанию 15, допустимо от 1 до 1440 — не больше суток), по расчёту стратегии позиция по нему ещё открыта, а цена не ушла в сторону прибыли больше чем на X % от цены сигнала (по умолчанию 0.1%; цена против сигнала — вход ещё лучше, он выполняется). Если последний сигнал — добор к позиции, которая по расчёту открыта, догоняется вся позиция: сначала первая нога (по рынку или лимиткой — как настроено в конфиге), затем добор (при входе лимиткой добор не ставится: добирать можно только в открытую позицию); возраст и цена проверяются по сигналу добора. Сигнал, по которому лимитка в расчёте ещё ждёт исполнения, тоже догоняется. О причине отказа бот пишет в чат и в журнал. Выключено по умолчанию.

**«Не ставить SL, пока метрики сильны» в автоторговле.** Опция конфига (`sl_hold_strong`) работает и на бирже, но только там, где у конфига включено «управлять»: вход (в том числе добор, вход лимиткой и по ходу) выполняется **без стопа**, только с тейками, если метрики последнего отчёта ещё удовлетворяют условию входа.
На каждой проверке конфига (при новом отчёте и раз в 5 минут) бот сверяет стоп на бирже с тем, что должно быть по расчёту сейчас: метрики остыли — ставит стоп по цене стопа расчёта (цена уже за стопом — закрывает позицию по рынку, как расчёт вышел бы по цене открытия), метрики снова сильны — снимает стоп,
стоп в безубытке после TP1 от метрик не зависит. Состояния в базе нет — сверка идёт с самой биржей, поэтому после перезапуска бота всё восстанавливается. Если «управлять» выключено, стоп ставится сразу, как обычно (потом его поставить некому). Пока метрики сильны, убыток на бирже не ограничен (кроме ликвидации);
если бот в это время не работает, стоп не появится до его возвращения (сторож предупредит). При пирамидинге на бирже одна позиция — один стоп: берётся самый близкий из действующих стопов ног. В карточке позиции такой стоп показывается как «не действует».
**Выход по стопу из расчёта, когда стопа на бирже не было.** Если рынок ушёл за стоп, пока метрики были сильны (стопа на бирже нет), а потом пришёл отчёт с остывшими метриками, расчёт видит выход «🛑 Стоп-лосс» уже на свече этого отчёта — позиции с признаком «открыта» в нём больше нет, и сверка стопа сама ничего не закроет. Поэтому для конфигов с «не ставить SL, пока метрики сильны» и «стоп-лосс по маркету» исполнение `SL` из расчёта закрывает позицию на бирже по рынку (запись `close_sl` в журнале, сообщение «позицию закрыл по рынку»). Если стоп-ордер на бирже всё же стоял и сработал сам, позиции уже нет и ничего не отправляется. Не удалось закрыть — бот запоминает это и повторяет при каждой проверке (раз в 5 минут и при новом отчёте), пока позиция не закроется, об ошибке пишет не чаще раза в час. У обычных конфигов стоп — ордер на бирже, бот его не дублирует.
Закрытие «целиком» по исполнению из расчёта (`WKND`, `REV`, `DS`, `SL` без стопа на бирже) берёт всю оставшуюся позицию, а не долю от первоначального размера, когда другие ноги пирамидинга уже закрыты: раньше после частичного тейка закрывалась только половина остатка.

**Стоп-лосс по маркету (`sl_market`).** Галочка в параметрах («стоп-лосс по маркету (решает отчёт)»), в конфиге и в `.env` (`SL_MARKET`, по умолчанию выключено). Стоп-ордера нет, касание цены стопа само позицию не закрывает.
Правило: цена дошла до стопа — система ждёт **следующий отчёт**. На новом отчёте: метрики **ниже порогов входа** (для лонга не выполнены сразу DL, DS и DG, если задан; для шорта зеркально) и цена **всё ещё за стопом** — позиция закрывается по рынку;
цена вернулась выше стопа — ничего; метрики **выше порогов** (условие входа выполнено) — не закрываем и ждём следующего отчёта, и так далее. Стоп в безубытке после TP1 остаётся обычным стоп-ордером и от отчётов не зависит; ликвидация (если моделируется) работает как обычно.
*В расчёте (бэктест, мониторинг, портфель, walk-forward):* решение принимается на свече, где пришёл отчёт (первая свеча не раньше времени отчёта) по её open; выход — по этому open с проскальзыванием, причина `SL` (в таблице сделок — подсказка «по маркету»),
убыток может быть больше заданного стопа; отчёты до касания и отчёт на свече входа не в счёт. Если включены обе опции, «не ставить SL, пока метрики сильны» не нужна — правило отчёта её заменяет.
*В автоторговле:* на бирже, где у конфига включено «управлять», вход (и добор, лимитка, вход по ходу) выполняется **без стоп-ордера**, только с тейками; на каждом новом отчёте бот сверяет цену (метрики берутся по этому отчёту) и закрывает позицию по рынку по правилу выше.
Обработанный отчёт запоминается в базе (по конфигу и бирже), поэтому после перезапуска он не обрабатывается дважды; отчёт старше `SIGNALBOT_MAX_AGE_MIN` (бот не работал) не применяется; не удалось закрыть — повтор при следующей проверке. Если «управлять» выключено, стоп-ордер ставится сразу, как обычно.
Если у позиции уже стоял стоп-ордер, при включении опции бот его снимает. При пирамидинге на бирже одна позиция — решает самый близкий из стопов ног. **Риск:** между отчётами (обычно раз в ~30 минут) убыток по позиции на бирже ничем не ограничен, а пока бот не работает, позицию никто не закроет.

**Повтор неудавшегося входа.** Если вход по сигналу не удался (ошибка биржи, лимит `TRADE_MAX_USD`, не хватило маржи, биржа не ответила), бот присылает сообщение и запоминает сигнал в базе. После перезапуска бота вход повторяется один раз, если: автомод «открывать» всё ещё включён, сигнал не старше `SIGNALBOT_MAX_AGE_MIN` (по умолчанию 180 мин) и по расчёту стратегии позиция по нему ещё не закрыта. Перед повтором, как и всегда, проверяется реальная позиция на бирже — дубль не откроется. Без перезапуска бот сам ничего не повторяет. Если не удалось закрыть встречную позицию при развороте, новая позиция поверх неё не открывается.

**От чего считается размер входа.** По умолчанию автомод берёт размер как в бэктесте: депозит из конфига (плюс накопленный результат при сложном проценте) × доля входа × плечо. Если депозит в конфиге не равен реальному капиталу (например, 200 000 $ в конфиге и 1 000 $ на счёте), у конфига выбирается «размер от баланса счёта» (сайт — выпадающий список у автомода; бот — кнопка «💰 База» в карточке): доля входа и плечо берутся из конфига, а база — реальный капитал на бирже. Перед каждым ордером проверяется свободная маржа: не хватает — ордер не отправляется, в журнал и в чат приходит причина. Если размер считается от депозита конфига, а он заметно больше капитала на бирже, на странице мониторинга и в карточке бота показывается предупреждение. Предохранитель `TRADE_MAX_USD` действует в любом режиме.

**Размер входа по конфигам.** У каждой стратегии на странице мониторинга есть строка «Размер входа»: доля депозита (маржа) и плечо (при пирамидинге — ещё доля и плечо добора); в боте — кнопка «📐» в карточке и команда `/size № % плечо`. Меняется размер новых входов и все расчёты по истории; сигналы и условия входа не затрагиваются, открытые на бирже позиции не меняются. Значения проверяются теми же границами, что в бэктесте.

**Аналитика.**
- *Портфель* (вкладка на странице мониторинга): галочками выбирается, какие стратегии учитывать (настройка хранится на сервере); у каждой стратегии в таблице есть поля «Вход, % деп.» и «Плечо» — сценарий «что если» только для расчётов портфеля (конфиги и автоторговля не меняются; кнопка «в конфиг» записывает размер в конфиг, ↺ возвращает значение из конфига); рядом с общим депозитом — переключатель сложного процента для ВСЕХ стратегий сразу (как в конфигах / включить / выключить, тоже только для расчётов портфеля); можно задать ОБЩИЙ депозит на все стратегии — тогда размер каждой сделки считается от общего баланса, а в итогах виден пик одновременно занятой маржи; график кривых двигается и масштабируется мышью, при наведении над каждой кривой подписано её состояние в $; кривые капитала всех стратегий рядом + общая, корреляция дневных результатов, суммарные открытые позиции по активам с предупреждениями (несколько стратегий в одну сторону, встречные позиции, маржа больше депозитов), блок реальной биржи.
- *Walk-forward* (бэктест, под Монте-Карло): подбор 1–2 параметров на окне и проверка на следующем, окна сдвигаются; рядом — исходные параметры на тех же проверках, эффективность и вердикт о подгонке.
- *Сводки и выгрузки.* `/digest daily|weekly|off|now` (или вкладка «Портфель»): результат за период, позиции, действия автомода, ошибки, капитал на бирже. `/export trades|log|fills` и кнопки на сайте — CSV сделок стратегий, журнала автоторговли и реальных исполнений.

**Кеш расчётов.** Результат стратегии не пересчитывается с нуля: для каждой (по набору параметров, источнику и активу) сохраняется снимок — состояние генератора входов, EMA фильтра тренда и уже закрытые сделки (`CACHE_DIR/runcache`, общий для веба и бота). При новых отчётах и свечах (по клику пользователя или в цикле бота) считаются только они и позиции, ещё не закрытые на момент прошлого расчёта; если история изменилась (докачаны старые свечи, правка файла) — считается заново. `RESULT_CACHE=off` отключает.
**Код проверен на имитации биржи (тесты), но не на живой сети — сначала прогоните его на тестовой сети.** Позиции по одному контракту на Hyperliquid «сливаются», поэтому доборы и стопы по ногам работают на общую позицию.

### Бот: тот же мониторинг в чате
`/monitor` (или `/m`) — одно сообщение с кнопками, которое правится на месте: список стратегий (статус, результат, автомод) → карточка стратегии (позиция по ногам, уровни, ликвидация, метрики, план) →
вкладки статистика / история / параметры / журнал; переключатели автомода (включение с подтверждением), пауза/возобновление, удаление (с подтверждением), скачать конфиг, экран «Биржа», тестовая позиция $1, «Автомод выкл. везде».
**🔴 Live** перерисовывает экран каждые ~20 с (30 мин, сообщение меняется только если данные изменились). `/hl`, `/bybit` и `/upscale` — подключение и состояние счетов, `/ex` — настройки конфига для биржи, `/positions` — открытые позиции текстом, `/tradelog [N]` — лог автоторговли файлом.

### Лог автоторговли
Весь флоу пишется в отдельный файл **`trading.log`** (рядом с базой; `TRADE_LOG_FILE` меняет путь; JSON по строке, ротация 5 МБ × 5): решения автомода (`auto_decision`), запросы к бирже (`order_request`), ответы (`order_ok`), сбои (`auto_fail`, `exchange_fail`, `order_fail` со стеком),
проверка и подключение счёта (`verify_*`, `account_connected`), переключения автомода, пауза, тестовые позиции. **Секреты вырезаются** (ключи, 64-значные hex, адреса маскируются). Свои записи — `/tradelog` в боте.
