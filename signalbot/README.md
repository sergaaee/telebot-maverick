# Бот сигналов Maverick

Отдельный Telegram-бот на **aiogram** (поднимается отдельно от backend/frontend), **многопользовательский**: у каждого пользователя сайта свои
конфиги стратегии (те же, что в интерфейсе), и каждый раз, когда по любому из них приходит **новый сигнал**, бот присылает его владельцу красиво
оформленным вместе со **статистикой конфига**
(сделки, winrate, PF, доходность от депозита, просадка в %, коэффициент Шарпа и т. д.).

Движок расчёта — тот же, что в интерфейсе (`backend/app/core`): правила входа, фильтры (остывание, ликвидации, тренд EMA), тейки частями,
безубыток, депозит/плечо, топ-коины. Бот ничего не торгует — только оповещает.

## Пользователи и привязка Telegram

Аккаунты общие с сайтом (SQLite `data/maverick.db`, `DB_FILE`). Регистрации нет — пользователей создаёт администратор в консоли:

```bash
python backend/cli.py user add ЛОГИН          # пароль спросит; первый пользователь — администратор
python backend/cli.py user list
```

Чтобы бот узнавал человека, Telegram привязывается к его аккаунту **одноразовым кодом**: на сайте меню пользователя (👤 вверху справа) →
«Привязать Telegram» → отправьте боту показанную команду `/link КОД` (код живёт 10 минут). Тому же можно научить консоль:
`python backend/cli.py user link-code ЛОГИН`. Не привязанный Telegram бот не слушает (кроме `/start` и `/link`). Один Telegram — один аккаунт.
Конфиги, команды и сигналы строго раздельные: чужие конфиги недоступны ни по номеру, ни по имени.

**Если раньше пользователь был один (вы):** при создании первого аккаунта `user add` сам переносит ваши прежние данные — состояние интерфейса
(`data/ui_state.json`), конфиги бота (`data/signalbot.json`, сигналы заново не придут) и Telegram id из `SIGNALBOT_CHATS`. Файлы остаются нетронутыми;
повторить перенос можно командой `user import-legacy ЛОГИН`.

**Общие данные.** История сообщений ботов и свечи в `data/` — одни на всех: пользователи ничего не качают заново, одинаковые расчёты у разных
пользователей за один цикл выполняются один раз.

## Запуск

```bash
cd signalbot
cp .env.example .env        # SIGNALBOT_TOKEN — токен от @BotFather
pip install -r requirements.txt
python run.py               # или из корня репозитория: python signalbot/run.py
```

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен — в `SIGNALBOT_TOKEN`.
2. Создайте пользователя (см. выше), привяжите Telegram.
3. Нужны данные: файлы истории (`SOURCE_*_FILE`) и свечи в `data/` из `backend/.env` — бот пользуется теми же. Свечи нового актива бот докачивает сам.

## Как добавить конфиг

В интерфейсе: **⬇ Скачать конфиг** (файл) или **Копировать** (текст). Дальше любой из способов:

- отправьте файл `.json` боту (подпись к файлу — имя конфига; без подписи имя берётся из источника и актива);
- вставьте скопированный JSON обычным сообщением;
- `/add Имя конфига {…JSON…}` — с явным именем (повторный `/add` с тем же именем обновляет конфиг);
- можно прислать сразу несколько: `{"configs": [ … ]}` или JSON-список.

Принимается и «голый» объект параметров. Недостающие поля берутся из текущих значений `backend/.env` и **фиксируются** в конфиге; неизвестные
поля пропускаются (бот напишет какие). Ошибки в значениях бот объясняет и ничего не сохраняет.

После добавления бот считает статистику и присылает карточку конфига. **Старые сигналы не присылаются** — только новые.

## Команды

| Команда | Что делает |
|---|---|
| `/list` | ваши конфиги, состояние, сколько сигналов отправлено |
| `/stats <№\|имя>` | свежая статистика конфига (и топ-коинов) |
| `/get <№\|имя>` | получить конфиг файлом (его можно загрузить в интерфейс) |
| `/rename <№\|имя> <новое>` | переименовать |
| `/link КОД`, `/unlink` | привязать Telegram к аккаунту сайта по коду / отвязать |
| `/pause`, `/resume <№\|имя>` | пауза/возобновление (пропущенное на паузе не присылается) |
| `/remove <№\|имя>` | удалить |
| `/check` | проверить новые сигналы прямо сейчас (не блокирует бота) |
| `/cancel` | остановить долгий подсчёт/загрузку свечей; ещё не посчитанные конфиги встают на паузу (вернуть по одному: `/resume <№>`) |
| `/status` | последние отчёты ботов, состояние подгрузки, цикл |

## Долгий первый подсчёт

Первый подсчёт конфига может быть долгим: если по активу ещё нет свечей, они скачиваются с первого отчёта (минутные свечи за месяцы — это сотни запросов
к бирже; по одной загрузке на актив, одинаковые активы у разных конфигов качаются один раз). Бот предупреждает об этом сообщением. Пока идёт подсчёт:

- уже посчитанные конфиги обрабатываются **раньше** новых, их сигналы не ждут чужих загрузок;
- `/pause`, `/remove` и `/cancel` действуют, как только очередь доходит до следующего шага (загрузка свечей прерывается между порциями, скачанное сохраняется);
- ошибка (например, биржа не отвечает с IP сервера) приходит сообщением один раз и видна в `/list`; повтор — автоматически каждый цикл;
- свечи окон топ-коинов (для их статистики) докачиваются **в конце цикла** и не дольше `SIGNALBOT_TOP_BUDGET_SEC` секунд, на карточку и сигналы они не влияют.

Лучше присылать конфиги по одному и дождаться карточки «принят», особенно если среди них новые активы.

## Что в сообщении о сигнале

сторона и актив · имя конфига и источник · время отчёта · **DG / DL / DS** отчёта, ликвидации, топ-коин · **план сделки** от текущей цены
биржи (вход, TP1–TP3 с долями, SL, перенос в безубыток) · объём позиции по депозиту/доле/плечу · для топ-коинов — своя сделка и уровни ·
**статистика конфига** по истории.

## Что считается «новым сигналом»

Бот присылает момент, когда стратегия **открыла бы новую позицию**: пока серия подтверждающих отчётов продолжается и позиция «открыта»,
повторные подтверждения не присылаются; после закрытия по TP/SL (или при смене стороны) следующее подтверждение — новый сигнал.
Сигналы, отсечённые фильтром тренда, не присылаются. Сигнал старше `SIGNALBOT_MAX_AGE_MIN` (бот был выключен) пропускается.

## Откуда берутся новые отчёты

Файлы истории дополняет подгрузка сообщений Maverick-ботов из Telegram. Её делает либо backend (`HISTORY_SYNC`), либо сам бот
(`SIGNALBOT_SYNC`, раз в `SIGNALBOT_SYNC_MIN` минут, по умолчанию 5). Если backend уже подгружает историю, поставьте `SIGNALBOT_SYNC=false`.
Нужны `TG_API_ID`/`TG_API_HASH` и один раз авторизованная сессия (`python backend/cli.py export …`). Токен бота (Bot API) читать
чужих ботов не умеет, поэтому подгрузка идёт от вашего аккаунта, как и раньше.

## Состояние и тесты

Конфиги — в таблице `configs` базы `data/maverick.db`. Тесты: `cd signalbot && python -m pytest -q`.
