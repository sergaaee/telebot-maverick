# Бот сигналов Maverick

Отдельный Telegram-бот (поднимается отдельно от backend/frontend). Хранит ваши **конфиги** стратегии (те же, что в интерфейсе) и каждый раз,
когда по любому из них приходит **новый сигнал**, присылает его красиво оформленным вместе со **статистикой конфига**
(сделки, winrate, PF, доходность от депозита, просадка в %, коэффициент Шарпа и т. д.).

Движок расчёта — тот же, что в интерфейсе (`backend/app/core`): правила входа, фильтры (остывание, ликвидации, тренд EMA), тейки частями,
безубыток, депозит/плечо, топ-коины. Бот ничего не торгует — только оповещает.

## Запуск

```bash
cd signalbot
cp .env.example .env        # SIGNALBOT_TOKEN — токен от @BotFather, SIGNALBOT_CHATS — ваш chat id
pip install -r requirements.txt
python run.py               # или из корня репозитория: python signalbot/run.py
```

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен — в `SIGNALBOT_TOKEN`.
2. Запустите `python run.py`, напишите боту любое сообщение — он ответит **вашим chat id**. Впишите его в `SIGNALBOT_CHATS` и перезапустите.
   Пока id не вписан, бот никого не слушает и конфиги не принимает (чужие сообщения игнорируются).
3. Нужны данные: файлы истории (`SOURCE_*_FILE`) и свечи в `data/` из `backend/.env` — бот пользуется теми же. Свечи нового актива бот докачивает сам.

## Как добавить конфиг

В интерфейсе: **⬇ Скачать конфиг** (файл) или **Копировать** (текст). Дальше любой из способов:

- отправьте файл `.json` боту (подпись к файлу — имя конфига; без подписи имя берётся из источника и актива);
- вставьте скопированный JSON обычным сообщением;
- `/add Имя конфига {…JSON…}` — с явным именем (повторный `/add` с тем же именем обновляет конфиг);
- можно прислать сразу несколько: `{"configs": [ … ]}` или JSON-список.

Принимается и «голый» объект параметров. Недостающие поля берутся из текущих значений `backend/.env` и **фиксируются** в конфиге; неизвестные
поля пропускаются (бот напишет какие). Ошибки в значениях бот объясняет и ничего не сохраняет.

После добавления бот считает статистику и присылает карточку конфига. **Старые сигналы не присылаются** — только новые.

## Команды

| Команда | Что делает |
|---|---|
| `/list` | конфиги, состояние, сколько сигналов отправлено |
| `/stats <№\|имя>` | свежая статистика конфига (и топ-коинов) |
| `/get <№\|имя>` | получить конфиг файлом (его можно загрузить в интерфейс) |
| `/rename <№\|имя> <новое>` | переименовать |
| `/pause`, `/resume <№\|имя>` | пауза/возобновление (пропущенное на паузе не присылается) |
| `/remove <№\|имя>` | удалить |
| `/check` | проверить новые сигналы прямо сейчас |
| `/status` | последние отчёты ботов, состояние подгрузки, цикл |

## Что в сообщении о сигнале

сторона и актив · имя конфига и источник · время отчёта · **DG / DL / DS** отчёта, ликвидации, топ-коин · **план сделки** от текущей цены
биржи (вход, TP1–TP3 с долями, SL, перенос в безубыток) · объём позиции по депозиту/доле/плечу · для топ-коинов — своя сделка и уровни ·
**статистика конфига** по истории.

## Что считается «новым сигналом»

Бот присылает момент, когда стратегия **открыла бы новую позицию**: пока серия подтверждающих отчётов продолжается и позиция «открыта»,
повторные подтверждения не присылаются; после закрытия по TP/SL (или при смене стороны) следующее подтверждение — новый сигнал.
Сигналы, отсечённые фильтром тренда, не присылаются. Сигнал старше `SIGNALBOT_MAX_AGE_MIN` (бот был выключен) пропускается.

## Откуда берутся новые отчёты

Файлы истории дополняет подгрузка сообщений Maverick-ботов из Telegram. Её делает либо backend (`HISTORY_SYNC`), либо сам бот
(`SIGNALBOT_SYNC`, раз в `SIGNALBOT_SYNC_MIN` минут, по умолчанию 5). Если backend уже подгружает историю, поставьте `SIGNALBOT_SYNC=false`.
Нужны `TG_API_ID`/`TG_API_HASH` и один раз авторизованная сессия (`python backend/cli.py export …`). Токен бота (Bot API) читать
чужих ботов не умеет, поэтому подгрузка идёт от вашего аккаунта, как и раньше.

## Состояние и тесты

Конфиги и служебное состояние — `data/signalbot.json` (`SIGNALBOT_STATE_FILE`). Тесты: `cd signalbot && python -m pytest -q`.
